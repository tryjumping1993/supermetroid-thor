# Porting guide (Milestone 3)

Milestone 3 translates the rest of the game's logic to native C++ **one routine at a time**, in
the style of the community Zelda 3 port: ported code reads and writes a 128 KiB WRAM mirror using
the same variable names and layout as the original, so an assembly routine and its C++ version
line up statement for statement. There is **no 65816 interpreter, no emulated CPU, no ROM-code
execution**. ROM is used only as read-only data (tables, instruction lists, tile graphics, text),
exactly as the M1/M2 decoders already do.

## Pieces

| Piece | Where |
| --- | --- |
| Disassembly (source of truth) | `reference/sm-disassembly/src/bank_XX.asm`, `memory.asm`, `labels.asm` (pinned; read-only). If the submodule is empty in your checkout, read it from the main checkout: `C:/Users/jblack/Documents/Programming/supermetroid-thor/reference/sm-disassembly/src`. |
| WRAM accessors | `native/generated/ram_map.hpp` (`WramNames`), generated by `tools/gen_ram_map.py` from `memory.asm` + `build/reference.sym`. Names equal the disassembly: `SamusXPosition()`, `Enemy_health(x)`, `Boyon_speed(x)`, `LevelData`-style arrays via `bytes_at`. |
| ROM label addresses | `native/generated/reference_labels.hpp` (`thor::labels::Name`, 24-bit) for banks $80–$B3. Address metadata only. Regenerate with `tools/reference_index.py`. |
| `Game` | `native/include/thor/game.hpp`: WRAM + ROM + registries for natively ported routines. |
| Session | Host of the running game (`session.cpp`); syncs its state with `Game` each tick until the corresponding subsystem is ported. |

## Translating a routine

* Accessors take an optional byte offset = the 65816 index register. `LDA $0F7A,x` →
  `g.Enemy_XPosition(x)`. `x` for enemies is the enemy **byte offset** (index × 0x40, `EnemyIndex()` = `$0E54`).
* Words wrap at 16 bits like the accumulator (`Word` proxy); write explicit casts for signed use
  (`int16_t(g.Enemy_XPosition(x))`, `Word::s()`), and mirror `CLC/ADC`, `SEC/SBC`, `CMP`, `BPL/BMI`
  carefully: carry/overflow/sign flags decide many branches. Keep the routine's label and asm
  address in a comment (`// $A2:87F7`) so reviewers can diff behavior.
* Return values that the original passes in the carry flag become `bool`; other register results
  become return values. Do **not** invent behavior: if a branch looks odd, port it as written.
* Data tables are read from ROM at runtime by label (`g.rom_w(labels::Foo + 2 * i)`); never copy
  ROM bytes into the source tree. Constants that are code immediates (`LDA #$0010`) are fine.
* Bank `$80:xxxx` shared helpers (RNG, DMA queue, palette, math, etc.) become methods/functions in
  `native/src/` named after their labels. Reuse what exists before adding; grep first.
* Graphics that the original DMAs to VRAM or palette RAM: until the PPU-facing layer lands, port
  the state changes (indices, palettes' target values) and leave a `TODO(vram)` marker at the
  DMA call; do not skip game-logic side effects.
* Sound/music queue calls (`JSL QueueSound...`) call `g.queue_sound(id)`/`g.queue_music(id)` no-op
  hooks (declared in `game.hpp` when the audio track lands).

## Registering routines

Enemy AI, PLM pre-instructions and similar indirect calls are keyed by the routine's **24-bit
label address**:

```cpp
void MainAI_Zoomer(Game& g, uint16_t x) { ... }                       // $A3:xxxx
InstructionResult Inst_Zoomer_Foo(Game& g, uint16_t x, uint16_t y) {  // y points after the command word
    return {uint16_t(y + 2)};                                          // stop=true for sleep/wait/delete
}
void register_zoomer(Game& g) {
    g.add_function(labels::MainAI_Zoomer, MainAI_Zoomer);
    g.add_instruction(labels::Inst_Zoomer_Foo, Inst_Zoomer_Foo);
}
```

Each species/PLM file exposes one `register_*` function and is called from
`Game::register_all` (`native/src/registry.cpp`). Unregistered routines are logged once
(`THOR_LOG_MISSING=1`) and skipped, so partially ported areas still run.

## Files and ownership (avoid merge conflicts)

New code goes in **new files** under `native/src/<area>/` (sources are globbed by CMake); edit
shared files (`session.cpp`, `game.cpp`, `content.cpp`, `renderer.cpp`) only for narrow hooks.

## Build and check

```
export PATH=/c/msys64/ucrt64/bin:$PATH        # MSYS2 UCRT g++ (also required at run time)
cmake -S native -B build/core -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build/core
build/core/thor_tests.exe ROM.sfc --milestone2   # 120+ focused checks
build/core/thor_tests.exe ROM.sfc --route tools/routes/landing_site_to_bomb_torizo.txt
```
